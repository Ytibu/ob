# 智能医疗系统开发文档

## 1. 项目概述

本文档描述了智能医疗系统的前后端开发规范，涵盖用户注册、登录、医疗信息管理（填写/修改）及医疗信息查看四个核心模块。

### 技术栈建议
- **后端**：Java(Spring Boot) + MySQL
- **接口规范**：RESTful API，请求/响应统一使用 JSON 格式

---

## 2. 通用约定

### 2.1 统一响应格式
```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

| code | 说明      |
| ---- | ------- |
| 200  | 成功      |
| 400  | 请求参数错误  |
| 500  | 服务器内部错误 |

## 3. 数据库设计

### 3.1 用户表 `users`

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | 用户ID |
| username | VARCHAR(50) | NOT NULL, UNIQUE | 用户名 |
| password | VARCHAR(255) | NOT NULL | 密码（加密存储） |
| phone | VARCHAR(20) | | 手机号 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 注册时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

### 3.2 医疗信息表 `medical_records`

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | 记录ID |
| user_id | INT | NOT NULL, FOREIGN KEY | 关联用户ID |
| height | DECIMAL(5,2) | | 身高(cm) |
| weight | DECIMAL(5,2) | | 体重(kg) |
| blood_type | VARCHAR(5) | | 血型（A/B/AB/O） |
| allergies | TEXT | | 过敏史（JSON或逗号分隔） |
| chronic_diseases | TEXT | | 慢性病史 |
| emergency_contact | VARCHAR(50) | | 紧急联系人 |
| emergency_phone | VARCHAR(20) | | 紧急联系电话 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

## 4. 接口详细设计

### 4.1 用户注册

#### 接口信息
- **URL**：`/api/auth/register`
- **Method**：`POST`
- **描述**：用户注册新账号

#### 请求参数
| 参数名      | 类型     | 必填  | 说明             |
| -------- | ------ | --- | -------------- |
| username | string | 是   | 用户名，4-20位字母/数字 |
| password | string | 是   | 密码，6-20位       |


#### 请求示例
```json
{
  "username": "zhangsan",
  "password": "123456",
}
```

#### 响应示例
```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "id": 1,
    "username": "zhangsan",
    "created_at": "2024-01-01T00:00:00Z"
  }
}
```


---

### 4.2 用户登录

#### 接口信息
- **URL**：`/api/auth/login`
- **Method**：`POST`
- **描述**：用户登录

#### 请求参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| username | string | 是 | 用户名 |
| password | string | 是 | 密码 |

#### 请求示例
```json
{
  "username": "zhangsan",
  "password": "123456"
}
```

#### 响应示例
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "user": {
      "id": 1,
      "username": "zhangsan",
    }
  }
}
```


---

### 4.3 医疗信息填写/修改

#### 接口信息
- **URL**：`/api/medical`
- **Method**：`POST`（填写）/ `PUT`（修改）
- **描述**：用户首次填写或修改医疗信息
- **鉴权**：需要

#### 请求参数
| 参数名               | 类型     | 必填  | 说明     |
| ----------------- | ------ | --- | ------ |
| height            | number | 否   | 身高(cm) |
| weight            | number | 否   | 体重(kg) |
| blood_type        | string | 否   | 血型     |
| allergies         | array  | 否   | 过敏史列表  |
| chronic_diseases  | array  | 否   | 慢性病史列表 |
| emergency_contact | string | 否   | 紧急联系人  |
| emergency_phone   | string | 否   | 紧急联系电话 |

#### 请求示例
```json
{
  "height": 175.5,
  "weight": 70.2,
  "blood_type": "A",
  "allergies": ["青霉素", "花粉"],
  "chronic_diseases": ["高血压"],
  "emergency_contact": "李四",
  "emergency_phone": "13900000000"
}
```

#### 响应示例
```json
{
  "code": 200,
  "message": "保存成功",
  "data": {
    "id": 1,
    "user_id": 1,
    "height": 175.5,
    "weight": 70.2,
    "blood_type": "A",
    "allergies": ["青霉素", "花粉"],
    "chronic_diseases": ["高血压"],
    "emergency_contact": "李四",
    "emergency_phone": "13900000000",
    "updated_at": "2024-01-01T00:00:00Z"
  }
}
```

#### 业务逻辑
1. 根据当前用户ID查询是否已有医疗记录
2. **首次填写**：创建新记录
3. **修改**：更新现有记录
4. 返回更新后的完整医疗信息

---

### 4.4 医疗详细信息查看

#### 接口信息
- **URL**：`/api/medical`
- **Method**：`GET`
- **描述**：获取当前登录用户的完整医疗信息
- **鉴权**：需要

#### 请求参数
无

#### 响应示例
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "user_id": 1,
    "height": 175.5,
    "weight": 70.2,
    "bmi": 22.8,
    "blood_type": "A",
    "allergies": ["青霉素", "花粉"],
    "chronic_diseases": ["高血压"],
    "emergency_contact": "李四",
    "emergency_phone": "13900000000",
    "created_at": "2024-01-01T00:00:00Z",
    "updated_at": "2024-01-02T00:00:00Z"
  }
}
```

#### 业务逻辑
1. 根据当前用户ID查询医疗记录
2. 若记录不存在，返回 `data: null` 或提示未填写
3. 自动计算 BMI（体重kg / 身高m²），保留一位小数

## 5. 前端开发要点

### 5.1 页面结构

| 路由 | 页面 | 说明 |
|------|------|------|
| `/register` | 注册页 | 用户名、密码、手机号 |
