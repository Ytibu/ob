## 目标概述
开发一个C++代码格式整理工具，实现特定的代码风格规范。该工具需要以命令行方式运行，对指定文件进行原地修改并备份原文件。

## 格式规范要求

### 1. 指针和引用符号位置
- **规则**：`*`和`&`符号紧贴变量名，而非类型名
- **示例**：
  - 正确：`int *A;` `double &B;`
  - 错误：`int* A;` `double& B;`

### 2. 逗号分隔符格式
- **规则**：逗号后不加空格
- **适用场景**：变量定义、函数参数、类构造函数初始化列表等
- **示例**：
  - 正确：`func(int a,int b);`
  - 错误：`func(int a, int b);`

### 3. 分号分隔符格式
- **规则**：分号前不加空格，分号后不加空格（循环控制语句中）
- **示例**：
  - 正确：`for (int i = 0;i < 10;++i)`
  - 错误：`for (int i = 0; i < 10; ++i)`

### 4. 函数体大括号空格处理
- **规则**：简短函数体去除大括号内部首尾空格
- **示例**：
  - 正确：`{return true;}`
  - 错误：`{ return true; }`

### 5. 控制语句括号空格处理
- **规则**：
  - 去除括号内部首尾空格
  - 保留控制语句与左括号之间的空格
- **示例**：
  - 正确：`for (int i = 0;i < 10;++i)`
  - 错误：`for ( int i = 0; i < 10; ++i )`

### 6. 控制语句与括号间距
- **规则**：`if`、`for`、`while`等与左括号之间保留空格
- **示例**：
  - 正确：`if (true)` `for (int i = 0;i < 10;++i)`
  - 错误：`if(true)` `for(int i = 0;i < 10;++i)`

## 执行接口
```
./codeformat filename
```
- **输入**：目标文件名
- **输出**：直接修改原文件
- **备份**：生成`filename.bak`备份文件

## 关键技术挑战

### 代码正确性验证
这是最核心的问题，需要确保格式整理不会破坏代码语义。

#### 验证策略建议：

**1. 语法完整性检查**
- 使用Clang/LLVM工具进行语法解析验证
- 确保修改后的代码能够通过编译器的语法检查
- 使用`-fsyntax-only`标志进行纯语法检查

**2. 预处理前后对比**
- 保留预处理指令的完整性和正确性
- 确保宏定义不会被错误修改

**3. 字符串和注释保护**
- 字符串字面量中的内容不应被修改
- 注释内容不应受影响
- 需要使用词法分析来识别这些特殊区域

**4. 增量验证方法**
- 逐行或逐块应用修改
- 每次修改后立即验证语法正确性
- 失败时回退到修改前状态

**5. 测试套件构建**
- 创建覆盖各种边界情况的测试文件集合
- 包括复杂的模板、宏、嵌套结构等
- 对比修改前后的AST（抽象语法树）是否一致

## 实现建议

### 技术选型
1. **使用Clang LibTooling**：最可靠的方式，基于AST进行精确修改
2. **使用正则表达式**：实现简单但需注意边界情况
3. **使用Python + 词法分析**：平衡开发效率和正确性

### 安全机制
1. **备份机制**：修改前强制备份
2. **原子操作**：先写入临时文件，验证成功后再替换
3. **回滚能力**：检测到错误时自动恢复

### 质量保证流程
1. 单元测试覆盖所有规则
2. 集成测试使用真实代码库
3. 差异化测试：确保修改前后代码行为一致
4. 性能测试：确保处理大型文件时不会超时

## 注意事项
- 该任务的核心挑战在于**正确性保证**，而非简单的文本替换
- 建议优先考虑使用成熟的解析工具（如Clang）
- 实现时需特别关注C++语法的复杂性和边缘情况
- 对于无法确定的情况，应保守处理（不修改）而非冒险修改
